## 1. DSP commands

### 1.1 Ports and timing (doc facts)

- Reset: "Write a "1" to the Reset port (2x6h) and wait for 3 microseconds", then
  write 0, then poll 2xEh bit 7 and read 0AAh; "Typically, the DSP takes about 100
  microseconds to initialize itself" (SBG:908-916). CS4232: "When bit D[0] of this
  register is set to a one and then set to a zero a reset of the Sound Blaster
  interface will occur" (C32:2396-2399). ES1868: poll "In a loop that lasts at least
  1 milliseconds" (E68:2325); ES1887: "Delay at least 10 msec" between the 1 and the 0
  (E87a:1746).
- Read data available: 2xEh bit 7 (SBG:959-977). Write buffer: 2xCh bit 7 clear means
  ready (SBG:982-1001). CS4232 states the opposite polarity, "D[7]=1 indicates ready"
  (C32:2417-2421); Inference: a data sheet error, every other source agrees with SBG.
- Command durations stated: D1h "a maximum of 112 milliseconds" (SBG:3920), D3h "a
  maximum of 220 milliseconds" (SBG:3941). No figure is given for any other command,
  for F2h, or for the delay from block end to IRQ.
- ESS command window during compatibility DMA: "Application software must send a
  command within 13 microseconds after the Busy flag goes high or the command will be
  confused with DMA data" (E68:2493-2497, Figure 18 at E68:2521-2530). Inference: this
  13 us is a write deadline for the command window, not an interrupt latency; the
  "13 us DSP latency" in notes/event-timer.md is not what this document measures.
- ESS 2xCh read, bit 6 "same as bit 7 of port 2xEh", bit 5 FIFO full, bit 4 FIFO
  empty, bit 3 FIFO half-empty, bit 2 processor IRQ (compatibility DMA complete), bit 1
  FIFO-HE IRQ, bit 0 "Interrupt request generated by DMA counter overflow in Extended
  Mode" (E68:3011-3024). Creative defines bit 7 only (SBG:885-889).

## 2. Interrupt semantics

### 2.1 Creative (doc)

- "The DSP generates an interrupt at the end of each DSP block transfer"
  (SBG:1526); single cycle: "The DSP will generate an interrupt after transferring the
  programmed number of bytes" (SBG:1590-1591); auto-init: "interrupts to the
  application at constant intervals, according to the programmed block transfer size"
  (SBG:1305-1306).
- Acknowledge, DSP below 4.xx: "each DSP interrupt is acknowledged by reading the DSP
  Read-Buffer Status port once" (SBG:1015-1017).
- 4.xx: four sources share one IRQ; mixer 82h bit 0 = 8-bit DMA or SB-MIDI, bit 1 =
  16-bit DMA, bit 2 = MPU-401, D7-D3 reserved; "A bit is set to 1 if the corresponding
  interrupt is triggered" (SBG:1026-1048). Acknowledge by reading "2xEh for 8-bit
  DMA-mode digitized sound I/O or SB-MIDI", "2xFh for 16-bit", "3x0h for MPU-401"
  (SBG:1050-1056). ISR order: transfer, exit command if any, acknowledge, then EOI
  (SBG:1530-1549).
- Nothing is said about a second request while one is pending, nor about latency.
  Inference: one status bit per source, cleared only by its acknowledge, means a
  second block end before the acknowledge is merged into the first.

### 2.2 ESS (doc)

- "Note that any read of port 2xEh will also clear any active interrupt request from
  the ES1868" (E68:2576-2579); "A read from port 2xEh will reset any IRQ request"
  (E68:3027). ES1869 Audio 1: "cleared by hardware or software reset, or an I/O read
  from port Audio_Base+0Eh. The interrupt request can be polled by reading from port
  Audio_Base+0Ch" (E69:1212-1216). One request for all formats in extended mode.
- Pending request survives a D0h race and can be cancelled before it is taken: "a
  pending interrupt request from the DMA completion is generated. The interrupt request
  can be cleared by reading port 2xEh before enabling interrupts" (E68:2508-2513).
- FIFO half-empty: "An interrupt request is generated on the rising edge of the FIFO
  Half-Empty flag" (E68:2925-2927); DAC: when the FIFO "changes from >=128 to < 128"
  (E68:2938-2940).
- Extended DMA counter: "The counter will be incremented after each successful byte
  is transferred via DMA" and in auto-init "an interrupt is generated whenever DMA
  switches from one half of the circular buffer to the other" (E68:3437-3457).
  Inference: the extended-mode block interrupt is raised when the last byte enters the
  256-byte FIFO, up to 256 bytes before it plays. For the event timer, the virtual ESS
  interrupt belongs at the 8237 position crossing the block, not at the played position.
- Audio 2 latch: 7Ah bit 7 "set high when the DMA counter rolls over to zero, or when a
  1 is written to this bit. The latch is cleared by writing a zero" (E68:3352-3362);
  masked by 7Ah bit 6 (E69:1220-1222).
- Edge behaviour: ES1869 masking via Config_Base+7h: "If an unprocessed interrupt
  remains active, it generates an interrupt request because the interrupt pin was low
  during the masked period and then went high" (E69:1308-1311). ES1887 new method:
  "Edge-generation logic ensures that each pending interrupt request will correctly
  signal the interrupt controller" (E87a:983-985).

### 2.3 CS4231A and FM (doc)

- CS4231A INT "remains set until cleared by a write of ANY value to Status register
  (R2), or by clearing the appropriate bit or bits (PI, CI, TI)" (C31:1520-1528); the
  timer gives "interrupts at fixed time intervals regardless of the time required to
  service the interrupt (assuming the interrupt is serviced before the next timer
  interrupt is generated)" (C31:1556-1560). Inference: an unserviced one is merged.
- OPL2/OPL3 timer flags stay "until reset" (OPL2:1510-1514); OPL3: "This flag is not
  reset unless RST is written" (OPL3:833-842).

### 2.4 Against uCDD

- Merge on block end: virtual_irq_tick does nothing new while `virtual_dsp_irq` is
  non-zero (irq.asm:127-130), which matches 2.1. But it tests the whole byte: a pending
  8-bit bit (e.g. an unacknowledged F2h) suppresses the 16-bit block bit. SBG gives the
  two sources separate status bits (SBG:1037-1048). Could matter (minor).
- Re-raise of an unacknowledged request after two periods (irq.asm:137-153) is a
  deliberate deviation: a real line stays high and an edge-triggered PIC sees no edge.
- Acknowledge does not withdraw the PIC request: 22Eh/22Fh reads clear only
  `virtual_dsp_irq` (trap.asm:1765-1779); `virtual_pic_request` stays, so a game that
  acknowledges with interrupts off still takes the interrupt. E68:2508-2513 says the
  read before STI cancels it. Could matter for timing tests (Miles F2h).
- F2h while the DSP bit is already set re-requests the PIC (trap.asm:873-879). With the
  line already high a real card gives no second edge. Inference for the Miles case
  (two F2h 3 us apart, one interrupt expected): once delivery is delayed by the event
  timer, F2h should only request the PIC when it raises the line (bit was clear).
- 82h returns only bits 0-1 (trap.asm:1806-1809); bits 7-3 are reserved per SBG:1047.
- ESS model: all formats on bit 0 / 22Eh (trap.asm:1453-1465) matches E69:1210-1216.
  22Fh on an ESS is the FIFO PIO port (E68:3028), harmless.

### 4.3 Physical ESS (wss_output.asm)

- ess_setup (363-416) follows the documented order: reset with 3 (365, E68:2825),
  C6h, E7h, B8h=04h, B9h=02h, B6h=00h, B7h=71h then BCh (175 = Table 11 signed 16-bit
  stereo, E68:2808-2846), A1h EEh (795.5k/18), A2h FBh (7.16M/5 = 1.432 MHz, roll-off
  17.5 kHz, inside 80-90% of 22.05 kHz), half rate A1h DCh / A2h F6h likewise, A8h bits
  1:0 = 01 (400-402), B1h/B2h keep 3:0 and set 50h (403-407), D1h then B8h=05h (69-72).
  ISR checks 2xCh bit 0 then reads 2xEh (sb16.asm .wss path), as E68:3024-3027 says.
- ess_identify (307-330) and ess_rate_adjust (263-294) agree with the BAh rows above;
  on the ES1878 the trim write zeroes the ADC offset, as the comment says.
- Risk: on an ES1887 with the new interrupt method active (7Fh bits 3:1 non-zero),
  B1h bit 6 means "Masks the interrupt for Extended mode DMA transfer complete" and
  bit 4 "Masks all audio 1 sources" (E87b:975-995, E87a:975-999). ess_setup's 50h
  would then mask its own interrupt. With 7Fh = 0 (the reset value, E87a:995) the chip
  "acts exactly as the ES1888" and 50h is right. Could matter only if a BIOS or an
  earlier Windows session left 7Fh set.
- Doc step 7 recommends about 100 ms before D1h (E68:2840-2846); the start sends it at
  once: a pop risk only.

## 5. CS4231A and CS4232

Doc facts.
- MCE is required for I9 (except PEN/CEN), the clock bits of I8, and SF/SPE; PEN/CEN
  change "on-the-fly" (C31:1087-1104, 1644-1655). "The DAC output is muted when MCE is
  set" (C31:1648-1650).
- Calibration runs when MCE goes 1 to 0, type from I9 CAL1,0: none (0, 40 the first
  time), converter 136, DAC 40, full 168 sample periods; poll I11 ACI (bit 5) until
  clear (C31:1131-1176, 1906-1918).
- INIT: R0 reads 80h while initialising or while resynchronising to a new clock; host
  polls R0 until 80h is gone before leaving MCE (C31:1120-1126, 1178-1206, 1658-1666).
  R0 after reset "010x0000" (C31:1662-1665); I9 reset "00x01000" (C31:1938); I12 reset
  "10xx1010", ID 1010 (C31:2017-2036).
- Formats (MODE 1): I8 FMT0/C/L: 8-bit unsigned, u-law, 16-bit LE, A-law; S/M; CFS
  table, 16.9344 MHz /384 = 44.1 kHz (C31:1850-1904). DMA base = samples-1, ADPCM
  bytes/4-1 (C31:1467-1500). R2 INT cleared by any write to R2 (C31:1634-1650).
- CS4232 SB Pro part: ports at SBbase+0..E (C32:2335-2390), reset by 1 then 0
  (C32:2396-2399), mixer defaults 99h/01h (C32:2394-2440), shares the WSS IRQ and
  playback DMA, "mutually exclusive" with the codec (C32:2339-2344).

Against the code.
- Physical (wss_output.asm:6-93, wss_codec.asm:33-61): I9=0Ch (CAL=01 converter, SDC)
  and I8=5Bh (16-bit LE stereo, XTAL2/384) with MCE (24-27), then wss_calibrate waits
  INIT, leaves MCE, waits ACI set then clear: matches C31:1148-1155 and the clock-change
  sequence. I15/I14 = PERIOD_FRAMES-1 (37-40) per C31:1472. R2 cleared before PEN
  (80-85). No deviation found. The ACI-set wait spins 65535 reads when calibration ends
  before it is seen (wss_codec.asm:43-50); harmless.
- Virtual WSS (wss_input.inc, wss_state.inc): ACI is held for 1024 output frames after
  any MCE exit (wss_input.inc:62-67, 241-246) whatever CAL1,0 and the codec rate; doc
  0/40/136/168 sample periods. I12 reads 0Ah (wss_state.inc:41) against the CS4231A's
  8Ah: the virtual codec presents as a CS4248/AD1848 look-alike. R0 bit 7 (INIT) never
  reads 1 (wss_input.inc:43). Format writes outside MCE ignored and I9 outside MCE
  keeps all but PEN/CEN (wss_input.inc:108-125), as the doc says. All harmless; the
  ACI length could matter to a driver that times calibration.

## 6. FM (pass-through)

- SBG: an SB Pro with OPL2 returns 06h at 388h, with OPL3 00h (SBG:451-454).
- YM3812: waits of 12 master cycles after an address write and 84 after a data write
  (OPL2:395-415; about 3.3 us and 23 us at 3.58 MHz). Timer 1 80 us steps, timer 2 320
  us, "Tov(ms) = (256-N1)*0.08" (OPL2:582-626). Register 04h: bit 7 IRQ RESET clears the
  flags and ignores the other bits; bits 6/5 mask T1/T2; bits 1/0 start T2/T1
  (OPL2:630-655). Status D7 IRQ, D6 timer 1 flag, D5 timer 2 flag; flags remain "until
  reset" (OPL2:1503-1514).
- YMF262: 32 master cycles (14.32 MHz, about 2.2 us) after address and data writes
  (OPL3:192-206, 163-175). Same timer and status bits; "This flag is not reset unless
  RST is written" (OPL3:486-519, 826-842). NEW is register 105h bit 0: "To use OPL3
  functions, write NEW='1' during initialization" (OPL3:313-323, 680-682).
- uCDD traps none of 2x0h-2x3h, 2x8h-2x9h, 388h (ports.inc), so detection runs on the
  chip. Inference: when `virtual_base` differs from the physical `sb_base` (allowed by
  setup.asm:672; only standby pairing requires equality, standby.asm:16-22), the FM
  ports at the virtual base +0..3 and +8..9 reach nothing and BLASTER-based OPL
  detection fails; 388h still works. The ESS chips carry their own FM at 2x0h-2x3h and
  388h-38Bh (E68:2995-2996, 3030), and Warcraft II's ESFM path uses 105h bit 7 (ISSUES.md:51).

## 7. Likely bugs, in order

1. M1 (trap.asm:411 with 426-433, 443-462): ESS mixer 32h/36h writes land in the
   internal voice-left and CD-left gain slots.
2. P1/E9 (trap.asm:744-747): 41h/42h take one argument on the ESS; the parser takes two.
3. P5 (trap.asm:875): F2h overwrites `virtual_dsp_irq`, losing a pending 16-bit bit.
4. 2.4 (trap.asm:1765-1779): an acknowledge does not withdraw a pending virtual PIC
   request; E68:2508-2513 says a 2xEh read before STI cancels the interrupt.
5. P2 (trap.asm:823-824, 359-361): 38h refused and its data byte parsed as a command.
6. E2/E8 (trap.asm:2142-2143, 1757-1764): ESS B1h/B2h IRQ/DMA decode bits and 2xCh
   status bits do not reflect the virtual card.
7. P4, P6, M2, M3, M4, E4, E11, irq.asm:127: could matter, see the tables.
