Introduction
UMC didn’t make “UM8881 HB4 Super Energy Star Green” technical reference manual public, so I
made my own to be able to add support into the Coreboot/SeaBIOS project. Pinouts were obtained
painstakingly by measuring pin-by-pin on two boards:
  • A-Trend ATC-1415 with a dead southbridge and NiCd damage
       – UM8881F 9536 ETA + UM8886BF 9545 DYS
       – 2x SIMM slots, single bank of up to 512 kiB L2 cache, no mouse, no VLB
  • Biostar MB-8433UUD-A, a Coreboot/SeaBIOS target
       – UM8881F 9552 ETS + UM8886BF 9602 DYS
       – 4x SIMM slots, limited dual bank L2 cache, mouse, no VLB
Therefore most of the information in this document is specific to these two motherboards. Other
motherboards may have a different pin mapping or use functionality not located on these two boards
(especially VESA local bus).
Further the register set was checked only on MB-8433UUD-A motherboard with Am5x86-133 CPU.
The functionality of some registers are too hard to decide (especially PM settings). If the chipset
designed some registers to have multiple functionality (not stateless), the finding it out would be
almost impossible.
So take this datasheet as always incomplete and speculative.

The chip functionality (pinouts, register set) depends on both suffix and revision markings. However
the basic functionality seems to be the same.

Suffix and revision analysis

Some chips may have sanded markings and they may be simply labeled as: “1/BT” and “6A/AY”. It
is likely an equivalent of UM8881F-BTx and UM8886AF-AYx respectively, although the third letter of
revision is uncertain (usually BTO, BTS and AYA, AYS, AYT respectively).
The omission of the third letter could point to a hypothesis the last letter doesn’t have any meaningful
value on the board design (no HW nor SW differences). Or it could just lead to a laziness :-D.
On the other hand, the first weeks of manufacture of the HB have genuinely two letter revision codes,
so it could be amount of manufactured chips (ex. more assembly lines).
The oldest HB seems to be from 9429 (BS or BA), after 9444 the 3-letter revision code appears (BCx,
BTx). There was no Cxx code and only like two occurrences of Dxx code. The first occurrence of Exx
code is from 9525 (Bxx revision was going in parallel). No Fxx ever appeared, so the development
probably ended up with Exx revision. The main production of the HB probably ended in the last week
of 1996 (last found datecode 9651). But during the exhaustive search a single datecode 9714 for
revision EYS was found on PC-Chips board. It could be a custom batch or just selling accumulated
parts. Interestingly there are revisions which are later in the alphabet.
The IBC has different part number suffixes (F, AF, BF and N). These have both SW and HW differences.
The oldest IBC which was found is F (suffix) from 9432. The first revisions were also two letters (AA,


                                                    7
AS). Since 9445 there are occurrences of F suffix with BS revision. The first AF suffix occurred in
week 9450 with revision AYS. The F suffix is then manufactured in parallel with a revision EYS. The AF
continues with revisions AYA, BYA and FYx until 9544. The first BF suffix appeared in 9539 with DYS
revision. This was developed into FXS revision in 9611. Until the end of the general manufacturing
in 9652 the revisions CYx and other FXx have appeared. The last suffix F occurred in 9638 with EYT
revision.
No IBC with suffix N was stored in the database as these seems to be combined mostly with pentium
generation HB.
A special case of 1997 date code was found thanks to Bits und Bolts in “Socket 3 Nightmare: New
Old Stock, But Then I Bricked It!” video, there are 5x IBC chips of the latest date code even found.
The markings are “UM8886BF 9724-FXT MM5G17”. The serial codes were the same.

Serial code analysis

The “serial” code (the last line of the chip marking) is almost always different. However there were
few chips with the same value.
Two HBs with the same “serial” code have other values same, with exception of “MA0508” (EYS vs
EYA, these could be mistake from photos). The IBC follows the same rule.
There are chips with the same datecode, suffix and revision, which have nearly the same serial code.
On the other hand, most of chips with the similar datecode have the serial code with high differences.
There is a correlation between first 3 letters and datecode.
Taking all this into the account, the “serial” code may be a different way to encode suffix, revision,
date, production line a/or a batch.

Host Bridge (HB) UM8881-F
The Host Bridge is a PCI based 486 chipset. It integrates:
  • 486 front side bus
  • DRAM controller
  • Up to L2 cache 1 MiB (dual bank/interleaved) or 512 kiB (single bank), write-back or write-
    through
  • Tag RAM
  • PCI busmaster
  • VESA Local bus support
  • Power management functions
No IDE controller is implemented in the HB. All communication with IBC and rest of the system is
done via PCI bus.


HB revisions
The HB comes in multiple revisions. EDO seems to be supported only from PCI revision 4 and higher.
Manual for Pine Technology PT-432B refers to the EDO capable HB as UM8881F/E, manual for Shuttle
HOT-433 as UMC8881F-Exx.
The PCI revision can be also check via software. The 32-bit register 0x8 in PCI configuration space
contains Revision ID field which shows the revision value.
NOTICE No HBs with values other than 4 were tested. This datasheet refers to HB PCI revision 4 in
all documentation.
You can see the value if you execute pciutils’s lspci:
00:10.0 Host bridge [0600]: United Microelectronics [UMC] UM8881F [1060:8881] (rev 04)
Or if you execute PCICFG.EXE in MSDOS:
PCI bus 00 device 10 function 00: Header Type 'non-bridge' (single-func)
Vendor: 1060    United Microelectronics (UMC)
Device: 8881    UM8881 HB4 486 PCI Chipset
Class:    06    bridge                  Revision:  04
Other revisions may or may not have other HB registers readable/writable.

ISA Bridge Controller (IBC) UM8886-F/AF/BF/N
The ISA Bridge Controller integrates most of the system’s glue logic and bridges PCI bus to ISA bus.
It’s features includes:
  • PCI arbiter for HB and regular PCI slots
  • ISA bus
  • PS/2 keyboard controller, optionally PS/2 mouse
  • Minor CPU control signals
  • IDE controller (only in AF/BF/N variants)
  • Interface to RTC chip
  • Up to 512 kiB flashable ROM BIOS
  • IBM PC compatible chipset (PIT, PIC, DMA, PPI) logic
  • Power management logic
  • RESET logic
  • Clock distribution


IBC suffixes
The IBC comes in 4 confirmed different variants marked with F/AF/BF/N suffixes.
It is highly probable F vs AF/BF will differ in pinout as F doesn’t implement any IDE controller. No
same motherboard models with F/AF variability were found.
Parts suffixed by AF and BF seems to be almost fully compatible without a huge board redesign.
Boards A-Trend ATC-1415, PCChips/Hsin Tech M921 (486) and PCPartner UMC Lite 486 seem to vary
between both variants. There may be some invisible changes on PCB though.
BF vs N variant definitely changes some pins functionality including power supply pins. N variant
seems to have crammed support for devices on notebooks (ex. encoded DMA requests, docking
and PC card signals and differently located PS/2 controllers). On ATC-1415 board with BF variant the
keyboard clock is connected to UM8886BF pin 57 but schematics for UM8886-N has this pin labeled as
PGP1/LDEV#/GA20, the keyboard data on BF leads to pin 56, which is called PGP0(RC#*) on variant


                                                 21
N. UM8886N can have the keyboard input on pin 54, which is labeled “SMI2#/LB2#/KBCI”. Also as
Pentium boards can use 66 MHz FSB, some parts of this variant will be clocked at this speed.
AF variant was found on a pentium board. It seems UM8886 is universal enough to be used as a
generic PCI/ISA bridge.
IDE is implemented only in AF/BF/N suffixed chips. The boards with F chip often use CMD640 or other
IDE controller solutions.
From the software point of view all variants differs. The AF has configuration registers for IDE located
at I/O port 0x108. The BF IDE controller uses a PCI config space. Also the BF variant can remap the pin
usage for PS/2 mouse (shared with ISA bus address signals). The N variant was not tested (no HW).
But from the schematics it is built as an evolution from BF variant. It also needs to have additional
configuration registers for notebook specific designs.


IBC revisions
As for revisions, no exact problems were reported, but it is generally recommended to have as latest
revision as possible :-).
It is possible i8042 controller in UM8886BF 9602 DYS doesn’t support 0xd3 command (= write byte to
the second PS/2 port output buffer). This will fail autodetection in linux kernel. It is possible BIOS
fixes this by emulating the command in an SMM handler. The UM8886BF 9602 DYS PCI arbiter supports
PCI bus masters behind PCI (and even PCIe) bridge cascade, but older parts may have bugs in its PCI
implementation (other 486 chipsets introduce multiple bus deadlocks if used with PCI bridges). IDE
support (especially higher speeds) may have bugs too.

Pins were traced on A-Trend ATC-1415 board and partially on Biostar MB-8433UUD-A board. The

Data bus for BIOS and address/data bus for RTC on ATC-1415 are buffered via 74F245 and then they
are connected to ISA data pins. BIOS/RTC cycle is distinguished from ISA cycle by DIR and /OE pins
of the buffer. Buffer 74F245 direction pin 1 is driven from UM8886-BF pin 41 XDIR. 74F245’s output
enable pin 19 is driven from UM8886-BF pin 40 XDEN.
The IBC creates only control signals of the IDE interface, the data signals are shared with the ISA bus
(via 74F245 buffers). The IDE bus cycle (primary or secondary) is distinguished from an ISA bus cycle
with /OE and DIR pins of F245 buffers.

IBC IDE controller (only AF/BF/N chip variants)
There is a difference between AF and BF/N variants. The UM8886-AF IDE is just an ISA controller,
whereas UM8886-BF or UM8886-N have IDE designed as an integrated PCI device. Both have some
proprietary configuration settings.
Using the integrated IDE will block the usage of both the ISA and PCI buses (instead of a dedicated
PCI IDE card), however the chipset is probably too simple to support any concurrent buses operations
anyway.
It seems I/O ports are aliased at 0x400 granularity (0x1f0, 0x5f0, 0x9f0, …) over the entire I/O port
space (excluding decoded PCI BARs).

IBC UM8886-AF IDE controller

The UM8886-AF FIFO is 8 bytes in size.
The presumably same IDE controller design was also sold as a discrete UM8673-F chip on a PCI card
but configuration set by jumpers, as discussed at UMC IDE/EIDE controller datasheets.

IBC UM8886-AF IDE config registers         IBC has a register window located at I/O port 0x108.
108     Index register
109     Read/write data register
Access needs to be unlocked by writing an unlock sequence. This sequence consists of writing a
value 0x4a followed by 0x6c to index port. After that you can write following register indexes to index
register and write/read data to/from the data register.
Access can then be locked again by writing a value of 0x34 to the index register.

IBC UM8886-BF/N IDE PCI controller

The UM8886-BF FIFO is 60 bytes in size. The controller doesn’t check sector size, multiple sector
transfers, ATA vs. ATAPI commands, etc. so it has to be told when data transmission direction changes
or finishes. A custom (nonstandard) IRQ 14/15 handler must check it and set the configuration from
filling to draining mode at the correct moment (and do it for each transfer). This means only a
specialised driver can use FIFO.
The UM8886-BF bus master does not support hardware scatter-gather, limiting its utility in a multi-
tasking OS as the driver has to watch 16-bit register 0x58 count down to zero before loading next
physical address.
There are also alignment restrictions leading to an unaligned head/tail that gets accessed in FIFO PIO
or plain PIO mode when doing a bus master read.

Super I/O (SIO) UM82C863-F, UM8663-AF/BF
These are a wide UMC family of ISA SuperIO chips. The features varies with entire family. Usage
spans between ISA/VLB I/O cards and 486 to Pentium motherboards. The descendants seems to be
used in P6 generation machines too. Possible features are:
  • Floppy drive controller
  • Parallel port, optionally with ECP
  • Two UART controllers, optionally with FIFO and IrDA
  • Gameport decoder
  • IDE control signals decoder
  • Integrates a crystal oscillator 24 MHz (or can use an external source)
Compared with other SIOs, these are very limited in functionality and have only 2-5 configuration
registers. The functionality can be pin strapped at power-on.

SIO types and variants
There are at least two UM8663 variants with AF and BF suffixes. The direct predecessor of UM8663
seems to be UM82C863-F. There is a register description in INTERLOGIC INDUSTRIES ASC486 VER. C
manual, which can be used to extrapolate the functionality to UM8663. The manual was found after
disassembling the BIOS to discover UM8663 registers :-D.
The manual for PT-627 specifies multiple versions, which each uses a different SIO:
  • PT-627A
      – UM8672/UM82C863/UM8667
      – EIDE + Standard I/O function
  • PT-627B
      – UM8672/UM8663/UM8667
      – EIDE + FIFO UARTs + ECP/EPP/SPP
  • PT-627C
      – UM8672/UM8668/UM8667
      – EIDE + FIFO UARTs + ECP/EPP/SPP + 2.88M FDD
  • PT-627D
      – UM8672/UM8662/UM8667
      – EIDE + FIFO UARTs + standard LPT
It seems UM8668 is a further improved version. The UM8662 chip seems to have worse functionality
than UM8663-AF/BF.
The motherboard PCChips/Hsin Tech M530 seems to use UM8663-BF or UM8670-F chips. With PCB
routing around SIO practically the same. The UM8670-F will be most likely more modern design.
Some 486 boards carry UM8669-F, for which the relation with UM8663 is completely unknown.
The UM8663-AF and UM8663-BF may have a limited interchangeability. For example photos of Sowah
Research SR-M401-A, PCChips/Hsin Tech M919 VER 3.2 and PCChips/Hsin Tech M507 can use both.
UM8663-AF/BF and UM82C863-F is not easily interchangeable. The oscillator input and output seems
to be switched in the packages.

SIO registers
The following access was found in BIOS for UM8663-AF variant:
108     Index register
109     Read/write data register
Similar to the IBC, the SuperIO access needs to be unlocked first. This is done by writing 0xaa to
the index port. Re-locking can be done by writing the value of 0x55. It seems any access must be
wrapped inside the lock/unlock sequence.
According to the manual the UM82C863-F implements CR0 and CR1 registers. The UM8663-AF has
an additional register CR2 and the UM8663-BF (untested) probably CR3 and CR4. UM8663-BF variant
probably supports IrDA on the serial port.
There are ISA I/O cards with UM82C863-F or UM8663-AF, where the configuration is set by jumpers.
This means SIOs mounted on motherboards are using this mechanism too, most likely in a form of

UM8667 I/O coupler
UM8667 is a complementary chip for UMC Super I/Os. It provides necessary level shifters and analog
processing. Integrated functionality:
  • Dual UART <-> RS232 level shifters for all signals
  • Single gameport interface with A/D sampling (556 like) with output to a partial ISA interface


UM8667 I/O coupler predecessor
SIOs UM82C863F/UM8663 can be coupled with UM8667 or its predecessor UM82C865F. Both should
have the same features, but UM82C865F includes a 24 MHz crystal oscillator so it can generate 24
MHz for SIO. It may be possible it has a support for dual joystick gameport. No further research has
be made.


UM8667 I/O coupler pin assignment
As UM8667 implements a partial ISA bus (to access gameport controller), but it doesn’t have ISA
address. There needs to be at least IOR and IOW signals (or some equivalent) from SIO so I/O coupler
can know when to read/write data (if gameport is enabled). Pins 5 and 6 are the candidates, but
that’s just a speculation (no HW to test on).
The TTL signals between RS232 level shifter and to/from SIO were not identified. It would require a
RS232 voltage level injector/monitor to observe them (too much work :-D).
